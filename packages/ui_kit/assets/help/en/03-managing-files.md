# Working with files

Everything file-related lives on the **File** menu (`Alt+F`). This chapter walks
through every command on it, in order, plus the two automatic behaviours — auto-load
and auto-save statistics — that quietly do some of this for you.

## Decks

- **Load deck...** opens a `.vok` file, replacing whatever is currently in memory.
- **Add/merge deck...** adds another deck's units onto the end of the one you have
  open, instead of replacing it. The merged deck must use the same mask; if it does not,
  or if bringing it in line with the current mask would lose data, the merge is refused
  rather than silently damaging either file.
- **Update deck from new version...** takes a new version of the open deck — typos
  fixed, units added — while keeping your own difficult flags. See
  [Sharing a deck](#sharing-a-deck).
- **Save deck** writes back to the file you opened. **Save deck as...** writes to a new
  path and switches to it, leaving the original file untouched.
- **Clear units from memory...** empties the workspace. After confirming, you choose
  between loading an existing mask file for the fresh start or minting a brand-new mask
  — the latter drops you straight into the [mask editor](05-mask-editor.md) to shape it.
  Nothing on disk is touched by this command; it only clears what is currently loaded.

## Masks

- **Load mask...** loads an `.inf` file as the mask linked to the current deck. This
  clears the units currently in memory, since a mask defines the shape those units must
  fit.
- **Save mask** / **Save mask as...** write the mask you are editing to its `.inf` file.
  These are the same commands the [mask editor](05-mask-editor.md)'s own OK button uses.

If a deck has no mask file linked to it yet — for instance because you built it from a
mask minted on the spot — opening the mask editor offers to create one from the deck's
embedded copy, so future edits have somewhere to be saved.

## Statistics

- **Load stats...** / **Save stats** / **Save stats as...** load or write a `.sta` file
  for the current deck.
- **Clear current stats...** erases every recorded attempt for the current deck,
  after confirming. This cannot be undone. If auto-save is on, the session you are
  clearing is written to its file first, so it survives on disk; the next session you
  start creates a new session file of its own rather than overwriting it.

These four are duplicated on the [Statistics](09-statistics.md) screen itself, so you
never have to leave it to save your results. They all act on the working record; the
deck's lifetime record is a second file kept automatically, described under
[The two records](09-statistics.md#the-two-records).

Both kinds of statistics file live in a folder named `statistics` beside the deck: for
`French/mydeck.vok` that is `French/statistics/`. The name is always the same — lower
case, never translated — so a deck folder shared between Windows and Linux, or between
an English and a German learner, means the same folder to everyone. The program creates
it the first time it writes a statistics file there; opening or browsing a deck never
does.

**Only the `statistics` folder is read.** A `.sta` file lying directly beside the deck,
where versions before 1.2.0 wrote them, is not found: auto-load does not offer it, the
deck shows as **not learned yet**, and the lifetime record starts again from zero in the
`statistics` folder. To keep such files, move them into the `statistics` folder beside
their deck before you next practise it.

## When the deck was edited elsewhere

Statistics are recorded per unit, so a deck that changed after its `.sta` was written —
edited in another copy of the program, regenerated by the converter, re-imported on the
phone — could easily end up with the wrong counters against the wrong units.

It does not. Every `.sta` stores a fingerprint of each unit beside its counters, taken
from that unit's question and answer fields. Loading statistics follows each fingerprint
to wherever its unit sits now, so units that were reordered, inserted or deleted leave
the rest of the deck's history exactly where it belongs. Remark fields are deliberately
left out of the fingerprint: rewriting a remark never costs a unit its results.

Two edits do reset results, knowingly:

- Changing a unit's **question or answer text** makes it a different unit — it starts
  from zero, and no other unit is affected.
- Changing a **field's role** in the [mask](05-mask-editor.md) re-fingerprints every
  unit, so the whole deck starts from zero.

Loading says nothing when nothing was lost, which is the normal case. When results were
lost, the status line reports how many units it happened to, for example **Statistics
for 3 units were reset — those units changed.** A `.sta` written before fingerprints
existed has none, and loads by position exactly as it always did.

Renaming or moving the **deck file** outside the program is a different matter. Every
statistics file is found by the deck's own name, in the `statistics` folder beside it —
`mydeck_alltime.sta` and `mydeck_20250114_183000.sta` belong to `mydeck.vok` and to
nothing else. Rename the deck in a file manager, or move it and leave them behind, and
they are orphaned: the program finds none of them, so there is nothing to auto-load, and
the lifetime record starts again from zero. Nothing is deleted, and nothing is lost for
good — rename the statistics files to match the deck's new name, and keep them in the
`statistics` folder beside it, and the link is restored. Saving the deck under a new
name from inside the program is not the same thing: the lifetime record follows the deck
into the `statistics` folder at its new location, unless a lifetime record already sits
there — that one belongs to another deck and is never overwritten, and the status line
says so.

## Sharing a deck

When two people learn from the same deck, each copy of the `.vok` keeps its own
[difficult flags](06-learning-sessions.md#marking-a-unit-difficult). The flags are
stored in the deck file itself, so the ones in your copy are yours, and the ones in
someone else's copy are theirs.

That matters when the deck's author sends round a **new version** — a typo fixed, a few
units added. Copying the new file over yours in a file manager gives you the author's
flags instead of your own, and your manual flags are lost for good. Instead, open your
own copy and choose **File ▸ Update deck from new version...**, then pick the new file:

- Your deck takes the new version's units, in the new order, and keeps its own file
  name and its statistics files. The statistics follow each unit as described under
  [When the deck was edited elsewhere](#when-the-deck-was-edited-elsewhere).
- Your flags move to the same units in the new version, each direction on its own,
  even where units were inserted or reordered. A unit whose question or answer was
  only slightly corrected keeps its flags too — though, being changed text, it starts
  its statistics from zero.
- The flags in the author's copy are ignored, and units that are new in this version
  start unflagged. Nothing is detected at this point: your own marking and the next
  automatic detection decide about them.
- The new file is only read, never changed, so you can pass it on as it is.

When it is done, the status line reports the result, for example **Updated “words.vok”
to the new version: 3 flags carried over, 1 dropped because their unit no longer
exists.** Each manual or automatic flag counts once per direction.

A file that uses a different mask is refused — it is not a version of this deck — and
so is one that could only be brought onto the newer mask revision by losing data; the
message then lists what would be lost, as updating the mask's other copies does. A
deck that has never been saved has no file to update: save it first.

## Auto-load and auto-save

Two independent toggles under **Options ▸ Statistics** save you the trip to the File
menu:

- **Auto-load statistics** — when you open a deck, the program looks in its
  `statistics` folder for a matching timestamped session file and, if it finds one, asks
  whether to load it.
  Nothing is loaded silently; you always see how old the file is and how much of the
  deck it covers before deciding.
- **Auto-save statistics** — when a learning session starts, if no statistics file is
  already associated with the deck, one is created automatically, named after the deck
  and the moment the session began, in the deck's `statistics` folder, which is created
  if it does not exist yet. From then on your progress is written to it as you go,
  without any further prompting.

**Keep last N session files...** (also under **Options ▸ Statistics**) bounds how many
of these auto-saved files pile up per deck: once you have more than the configured
count, the oldest in the deck's `statistics` folder are deleted after each new one is
written. Set it to 0 to keep every file.

## Exit

**Exit...** asks for confirmation, then — if auto-save is on — saves your statistics one
last time before closing. The window's own close button (the X in the title bar) goes
through exactly the same sequence, so there is no way to lose a session's results by
closing the window instead of using the menu.
